# Review of 104 legacy location paths

Reviewed 2026-09-21 against the local redesign database and the 2026-08-14 production reference export.

Twenty confirmed spelling/spacing/abbreviation aliases were added through the manual source. Nineteen aliases already existed. **39 of the 104 old paths now resolve; 65 remain unresolved. All 104 old location IDs remain absent.** A path alias does not restore a retired location ID.

The [complete review](review-104.csv) retains every original ID and path, candidate IDs and paths, individual findings, next actions, and the linked agencies' current addresses and locations. Candidate targets are suggestions or rejected comparisons, not approved mappings. Current agency assignments are observations, not independent proof that two places are equivalent. Every row has now been checked against the saved 2025 Census inputs. A blank external source means no separate external community-history source was used; the Census checks are recorded in the CSV and detailed evidence below.

## Confirmed agency-resolution defect

**The Census tree checks pass, but agency assignments do not consistently follow the geocoded point.** The 104 legacy location rows link to 123 agencies still present in the current database. Of those, **46 assigned place polygons do not contain the agency's stored coordinates**. [Every checked agency, address, coordinate, assigned path, and containing Census shape](agency-point-check.json) is recorded here; the CSV also identifies the affected agencies for each of the 104 rows.

Sam Rayburn ISD Police has coordinates **33.76749429006, -96.10511487177**, which are inside **Fannin County** and no Census place. Its assigned Ivanhoe path is in **Tyler County**, whose place polygon does not contain that point. The current resolver first tries point-in-place, then a city path in the containing county, then a unique same-name place anywhere in the state, then a nearest place. Those latter choices override the spatial evidence and violate the user's stated requirement. See `src/cli/import/artifacts/location-resolution.ts`, `LocationPathDataContext.getPlaceContainingPoint`, particularly the statewide-name and nearest-place branches. The current code expressly refuses a county-only answer because of an assumed website projection requirement; that assumption must not override the required point-in-shape behavior.

The two Medina agencies have identical stored coordinates **26.9289548, -99.2614176**, inside Medina CDP in **Zapata County**. For them, point-in-shape agrees with the assignment, but the stored points conflict with the Bandera County community and address evidence. This is a separate coordinate/geocoding provenance problem. It is not established that the statewide-name branch caused those two assignments.

No agency coordinates, agency assignments, resolver code, or resolved-property cache entries were changed by this alias batch. Correcting the resolver and existing cached assignments remains necessary; the twenty spelling aliases do not fix that defect.

## Is the Census import losing locations?

**No Census-import loss was found explaining these 104 differences.** Reconstructing the canonical tree from the saved 2025 Gazetteer files and hierarchy produced exactly all **35,249 current paths**, with no missing or extra paths and no display-name, level, or parent mismatch. For all 104 audit rows, the review checked the original path, any Census-generated alias, same-name places in the state, proposed targets, and the linked agencies' current locations.

The review independently recomputed county intersections from the saved raw TIGER polygons for **96 relevant Census places across nine states**. Every overlap and county choice agreed with the saved hierarchy. In particular, all **19 previously existing aliases** are valid same-place, multiple-county aliases. A county difference is not itself an import defect.

The missing paths have several different causes:

The Census place dataset contains incorporated places and Census-designated places; it is **not a list of every named community or mailing city**. The Census Bureau explicitly explains that not every community appears in its place products. See [Understanding Place in Census Bureau Data Products](https://www.census.gov/content/dam/Census/data/developers/understandingplace.pdf). The old production paths include geographic labels beyond the coverage and exact naming of these saved Census inputs. Their absence is not evidence that a source record was dropped during import.

[All 104 Census checks](census-check-104.json) retain each row's source GEOIDs, raw county-overlap evidence, current targets, and comparison results. [The CSV](review-104.csv) provides the compact row-by-row version. These checks establish location-tree and relevant county-hierarchy consistency, not a complete test of every geometry column or every agency address assignment.

[Ivanhoe in Fannin County](https://www.tshaonline.org/handbook/entries/ivanhoe-tx) is distinct; the historical source also connects it to Sam Rayburn ISD. Liberty Hill Police (`cm7a0bgos0400ewvgseubfmii`) currently points to **Liberty in Liberty County**, while the name candidate is Liberty Hill in Williamson County. Its address needs confirmation before correction. Several generic state-agency records currently carry Abbott, TX, so those records cannot corroborate Connecticut, Hawaii, Idaho, or Tennessee geography.

City-path continuity requires a separate decision from county equivalence.
