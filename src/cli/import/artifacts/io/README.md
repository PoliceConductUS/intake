# io

## Overview

Hand-written canonical IO for the envelope kinds `ArtifactMutation`,
`ArtifactMutations`, `DatabaseMutations` and `DatabaseMutationsDebug`. Each is
exported as an object with `kind`, `schema`, `new`, `read` and `write`.

The directory also holds the reader that sends one database mutation file to
the matching generated kind (`DatabaseMutation.ts`), helpers that count
mutations, and the shared read-ref path resolution (`envelope-ref.ts`).

All disk access goes through `src/shared/io/internal/yaml-document.ts`. File
names come from `src/shared/io/resource.ts:yamlResourcePath`:
`<encodeURIComponent(metadata.name)>.<kind>.yaml`.

Callers are `src/cli/import/artifacts`, `src/cli/data/chain.ts` and
`src/cli/replay/database-mutations`.

## Interface

- `ArtifactMutation.ts:ArtifactMutation` -
  `{ kind, schema, new(input), read(pathOrRef, options?), write(directory, envelope) }`.
- `ArtifactMutation.ts:artifactMutationSpecSchema` - spec
  `{ target, operations }`. The file also exports
  `artifactMutationTargetSchema`, `artifactMutationOperationSchema`,
  `artifactMutationOperationBaseSchema` and
  `artifactMutationOperationSourceSchema`, and the types
  `ArtifactMutationEnvelope`, `ArtifactMutationInput`, `ArtifactMutationSpec`
  and `ArtifactMutationOperation`.
- `ArtifactMutations.ts:ArtifactMutations` -
  `{ kind, schema, new, read(filePath, { raw? }), write, digest(filePath) }`.
  `read` without `raw: true` replaces each `ref` item with the spec of the
  `ArtifactMutation` it points to.
- `ArtifactMutations.ts:artifactMutationItemSchema` - an item is an inline spec
  or `{ ref: { path, kind: "ArtifactMutation", sha256? } }`. The ref form is
  exported as `ArtifactMutations.ts:artifactMutationReferenceSchema`. The file
  also exports the types `ArtifactMutationsEnvelope` and
  `ArtifactMutationsInput`.
- `DatabaseMutation.ts:readDatabaseMutation` - `(pathOrRef, options?)`; takes
  the kind from `ref.kind` or the file name and calls that kind's `read` from
  `importMutationEnvelopeTypes`.
- `DatabaseMutation.ts:parseDatabaseMutationKind` - `(kind)` returns
  `{ operation, recordKind }`.
- `DatabaseMutation.ts:DatabaseMutationEnvelope` - the type
  `readDatabaseMutation` returns:
  `{ apiVersion, kind, metadata, spec }`.
- `DatabaseMutationCounts.ts:countDatabaseMutations`,
  `DatabaseMutationCounts.ts:incrementDatabaseMutationCounts`,
  `DatabaseMutationCounts.ts:emptyDatabaseMutationCounts`,
  `DatabaseMutationCounts.ts:formatDatabaseMutationCountLines` - count
  mutations in total and per record kind, and format the counts as text lines.
- `DatabaseMutationCounts.ts:DatabaseMutationCounts`,
  `DatabaseMutationCounts.ts:DatabaseMutationCountable` - the counts type and
  the type of a mutation that can be counted.
- `DatabaseMutations.ts:DatabaseMutations` -
  `{ kind, schema, new, build, read(pathOrRef, { raw? }), write }`. `build`
  creates the envelope without validating its mutations.
- `DatabaseMutations.ts:databaseMutationItemSchema` - an item is an inline
  mutation (`databaseMutationInlineSchema`) or a ref
  (`databaseMutationReferenceSchema`). The file also exports the types
  `DatabaseMutationItem`, `DatabaseMutationInline`,
  `DatabaseMutationsEnvelope` and `DatabaseMutationsInput`.
- `DatabaseMutationsDebug.ts:DatabaseMutationsDebug` -
  `{ kind, schema, new, read, write }`.
- `DatabaseMutationsDebug.ts:debugDatabaseMutationItemSchema` - an item is a
  ref (`databaseMutationReferenceSchema`) or an inline mutation
  (`DatabaseMutationsDebug.ts:debugDatabaseMutationInlineSchema`). The file
  also exports the types `DatabaseMutationsDebugEnvelope` and
  `DatabaseMutationsDebugInput`.
- `envelope-ref.ts:resolveReadPath` - `(pathOrRef, options, defaultKind)`
  returns `{ filePath, kind?, sha256? }`.
- `envelope-ref.ts:EnvelopeReadRef` - `{ path, kind?, sha256? }` or that
  object wrapped as `{ ref }`.
- `envelope-ref.ts:refValue` - normalizes a string, `{ path }` or `{ ref }` to
  `{ path, kind?, sha256? }`.
- `envelope-ref.ts:EnvelopeReadOptions` - `{ expectedNamespace?, relativeTo? }`.
- `<RecordKind>Create.ts`, `<RecordKind>Read.ts`, `<RecordKind>Update.ts` -
  generated canonical IO for the per-kind mutation envelopes; see
  [Generated Mutation IO](#generated-mutation-io) below.

## Generated Mutation IO

This folder holds one generated canonical IO module per database mutation
envelope kind, named `<RecordKind>Create.ts`, `<RecordKind>Read.ts` and
`<RecordKind>Update.ts`, plus a generated `index.ts`.

Each of these files is generated by `scripts/generate-envelope-types.ts` (first
line: `// Generated by scripts/generate-envelope-types.ts. Do not edit.`). Do
not edit them. Change the generator and run
`npm run generate:envelope-types`. On each run the generator deletes and
rewrites every file in this folder and in `src/shared/io/` that starts with
that line, and throws rather than overwrite a file that does not.
`test/generated-files.integration.test.ts` requires those files to equal the
generator output. The generator reads the database schema, so it throws when
`DATABASE_URL` is unset.

The generator takes the list of kinds from `IMPORT_ARTIFACT_KINDS` and
`RECORD_KIND_BY_ARTIFACT_KIND` in `scripts/lib/entity-spec-generator.ts`, and
the three operations (`create`, `read`, `update`) from
`src/shared/io/import-operations.ts`. The module text comes from the inline
templates `mutationModule`, `envelopeSupport` and `mutationIndexModule` in the
generator.

The 29 record kinds, each with a Create, Read and Update module (87 modules):

- `Agency`, `AgencyArrestProfile`, `AgencyPersonnel`, `AgencyPhoneNumber`
- `ArrestProfile`, `AuthorityLicense`
- `CivilCase`, `CivilCaseLink`, `CivilCasePersonnel`
- `CoverageHomepagePlacement`, `CoverageHomepageWindow`, `CoverageLink`,
  `CoverageLinkAgencyPersonnel`
- `DataAnnotation`
- `Discipline`, `DisciplineAgencyPersonnel`
- `FederalAgency`
- `License`, `LicenseAction`, `LicensingAuthority`
- `LocationPath`, `LocationPathAlias`, `LocationPathGeometry`
- `Personnel`, `PersonnelEducation`, `PersonnelPhoto`
- `Review`, `ReviewLink`, `ReviewPersonnel`

The three modules of a kind differ only in their spec. The `Agency` modules
are the examples cited here; every other kind repeats them with its own name.

Interface:

- `index.ts:importMutationEnvelopeTypes` - the only export
  of `index.ts`: an object holding all 87 envelope-type objects, keyed by
  envelope kind.
- `AgencyCreate.ts:AgencyCreate` -
  `{ kind, schema, new(input), read(pathOrRef, options?), write(directory, envelope) }`.
  `write` returns `{ path }`. The same object shape is exported as
  `AgencyRead.ts:AgencyRead` and
  `AgencyUpdate.ts:AgencyUpdate`.
- `AgencyCreate.ts:AgencyCreateEnvelope`,
  `AgencyCreate.ts:AgencyCreateInput` - the envelope type
  and the type `new` takes. Every module exports the same pair as
  `<Kind>Envelope` and `<Kind>Input`.
- `AgencyCreate.ts:specSchema` - `AgencyCreateSpec` from
  `src/shared/io/entity-specs.ts`.
- `AgencyRead.ts:specSchema` - an empty object.
- `AgencyUpdate.ts:specSchema` - `{ operations }`, a list
  of `set` and `check` operations.

Invariants:

- `AgencyCreate.ts:schema` - `.strict()` on the envelope
  and on `metadata`; `apiVersion` must equal `INTAKE_API_VERSION`; `kind` must
  be the module's literal kind; `metadata.name` and `metadata.namespace` must
  be non-empty.
- `AgencyCreate.ts:parseAgencyCreate` - `new`, `read` and
  `write` all parse through it; it throws `<Kind> is malformed at <path>.`.
- `AgencyCreate.ts:readAgencyCreate` - throws when
  `ref.kind` is not the module's kind, when `ref.sha256` is given and does not
  match the file, and when `expectedNamespace` is given and does not match
  `metadata.namespace`.
- `AgencyRead.ts:specSchema` - `spec` must be an empty
  object (`.strict()`).
- `AgencyUpdate.ts:specSchema` - `.strict()`;
  `operations` has at least one item.
- `AgencyUpdate.ts:operationSchema` - an operation is
  `set` (`from`, `to`) or `check` (`value`), with `path`, `reason` and
  `source`. `path` must be a field name of `AgencySpec`; a `path` that
  contains `.` is rejected. `to` and `value` must pass that field's schema.
  `from` must pass it too, except that a `from` of `undefined` is not
  checked. Not exported.

Side effects:

- `AgencyCreate.ts:readAgencyCreate` - reads one YAML
  file.
- `AgencyCreate.ts:writeAgencyCreate` - writes
  `<directory>/<encodeURIComponent(metadata.name)>.AgencyCreate.yaml` and
  creates the parent directory.

## Invariants

- `ArtifactMutation.ts:schema` - `.strict()` on the envelope, `metadata`,
  `spec`, `target`, each operation and each operation source; `apiVersion`
  must equal `INTAKE_API_VERSION` and `kind` must be `ArtifactMutation`.
- `ArtifactMutation.ts:artifactMutationTargetSchema` - `target.kind` must be
  `Agency`, `Personnel` or `AgencyPersonnel`.
- `ArtifactMutation.ts:artifactMutationSpecSchema` - at least one operation.
  For `Personnel` and `AgencyPersonnel` targets the operation `path` must be
  one of the listed fields.
- `ArtifactMutation.ts:artifactMutationOperationBaseSchema` - `action` is
  `set`; `reason` and `source` are required; `path` is split on `.` and no
  segment may be empty.
- `ArtifactMutation.ts:requireValueForSet` - a `set` operation must carry its
  own `value` property.
- `ArtifactMutation.ts:readArtifactMutation` - throws on a `ref.kind`
  mismatch, on a sha256 mismatch when `ref.sha256` is given, and on a
  namespace mismatch when `expectedNamespace` is given.
- `ArtifactMutations.ts:schema` - `.strict()`; `spec.mutations` has at least
  one item.
- `ArtifactMutations.ts:artifactMutationSpecFromRef` - a referenced
  `ArtifactMutation` is read with `expectedNamespace: "manual"`.
- `ArtifactMutations.ts:readArtifactMutations` - throws on a sha256 mismatch
  when `ref.sha256` is given, and on a namespace mismatch when
  `expectedNamespace` is given.
- `DatabaseMutation.ts:kindFromReadInput` - when no `ref.kind` is given, the
  kind is taken from the file name with the pattern `^.+\.([^.]+)\.ya?ml$`,
  and a name that does not match throws
  `DatabaseMutation filename is malformed`. `.yml` is accepted. The kind is
  the part between the last two `.`, so the name part may contain `.`.
  Not exported.
- `DatabaseMutation.ts:readDatabaseMutation` - throws
  `Unsupported DatabaseMutation kind` when the kind is not in
  `importMutationEnvelopeTypes`.
- `DatabaseMutations.ts:databaseMutationReferenceSchema` - `ref.kind` must be
  in `IMPORT_MUTATION_KINDS` or be `DatabaseMutations` (a chunk file).
- `DatabaseMutations.ts:databaseMutationInlineSchema` - `kind` must be in
  `IMPORT_MUTATION_KINDS` and `spec` must pass that kind's generated schema.
- `DatabaseMutations.ts:MUTATIONS_PER_FILE` - a file holds at most 5000
  mutations; `writeDatabaseMutations` splits a larger set into chunk files.
- `DatabaseMutations.ts:readDatabaseMutations` - throws on a sha256 mismatch
  when `ref.sha256` is given, and on a namespace mismatch when
  `expectedNamespace` is given. Chunk files and single-mutation refs are read
  with `expectedNamespace` set to the top-level envelope's namespace. A chunk
  ref is read as a ref relative to the file that names it, so
  `resolveReadPath` rejects a path that leaves that file's directory and the
  chunk's bytes are checked against `ref.sha256`.
- `DatabaseMutations.ts:writeDatabaseMutations` - a chunk envelope is named
  `<name>-<index>` and carries only `name` and `namespace` in its metadata. A
  ref item's path, relative to the top-level file's directory, is rewritten
  relative to the chunk directory.
- `DatabaseMutationsDebug.ts:schema` - `.strict()`; `metadata.status`, when
  present, must be `failed`.
- `DatabaseMutationsDebug.ts:debugDatabaseMutationInlineSchema` - `kind` must
  be in `IMPORT_MUTATION_KINDS`; `spec` is any record. Unlike
  `databaseMutationInlineSchema`, it is not checked against the kind's
  generated schema.
- `DatabaseMutationsDebug.ts:readDatabaseMutationsDebug` - throws on a
  `ref.kind` mismatch, on a sha256 mismatch when `ref.sha256` is given, and on
  a namespace mismatch when `expectedNamespace` is given.
- `envelope-ref.ts:resolveReadPath` - a relative path in a ref object needs
  `relativeTo` and must not leave that file's directory. A string argument,
  relative or not, and an absolute ref path are returned as given, with no
  check.

## Side Effects

- `ArtifactMutation.ts:readArtifactMutation` - reads one YAML file.
- `ArtifactMutation.ts:writeArtifactMutation` - writes
  `<directory>/<name>.ArtifactMutation.yaml`.
- `ArtifactMutations.ts:readArtifactMutations` - reads the file, and one file
  per `ref` item unless `raw: true`.
- `ArtifactMutations.ts:writeArtifactMutations` - writes
  `<directory>/<name>.ArtifactMutations.yaml`.
- `DatabaseMutation.ts:readDatabaseMutation` - reads one YAML file through the
  generated kind's `read`.
- `DatabaseMutations.ts:readDatabaseMutations` - reads the file, then every
  chunk file and every single-mutation ref file unless `raw: true`.
- `DatabaseMutations.ts:writeDatabaseMutations` - writes
  `<directory>/<name>.DatabaseMutations.yaml`. Above 5000 mutations it also
  writes chunk files under `<name>.DatabaseMutations.records/`, and the
  top-level file holds only refs with a sha256.
- `DatabaseMutationsDebug.ts:writeDatabaseMutationsDebug` - writes
  `<directory>/<name>.DatabaseMutationsDebug.yaml`.
- `DatabaseMutationsDebug.ts:readDatabaseMutationsDebug` - reads one YAML
  file.
